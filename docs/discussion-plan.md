# План обсуждения

Темы, которые нужно обсудить и решить до начала реализации. По итогам решения переносятся в [overview.md](overview.md) и [functional-requirements.md](functional-requirements.md). Технические детали opencode: [opencode-integration.md](opencode-integration.md).

## 1. Подключение к opencode
- Выбрать способ подключения: FastAPI по HTTP, фронтенд напрямую или Node-прослойка. Предварительно выбран FastAPI-прокси.
- Решить, как запускать opencode: отдельный контейнер или в одном образе с бэкендом.
- Решить, как получать Python-клиент: генерация из OpenAPI или ручные вызовы.
- Зафиксировать версию opencode.

## 2. Безопасность на VPS
- Встроенная авторизация или внешняя защита.
- Можно ли использовать механизм pairing из opencode.
- Изоляция агента и набор `permissions` в конфиге opencode.
- Защита `fs/write` от записи вне проекта.
- Хранение GitHub Personal Access Token.

## 3. Хранение данных
- История чатов: только в БД opencode или экспорт в репозиторий (`session.export`).
- Тома docker compose: репозитории, БД opencode, конфиги.
- Бэкапы.

## 4. Git
- Конфликты при pull: нужна ли помощь в их разрешении.
- Ветки: входят ли в первую версию, использовать ли worktree.
- Генерация сообщения коммита ИИ (`session.generate`).
- Взаимодействие ручных коммитов с откатом правок агента (`session.revert`).
- Библиотека для git в бэкенде: `subprocess`, pygit2 или GitPython.

## 5. Модель проекта
- Как проекту (папка в репозитории) соответствует `location` в opencode.
- Конфигурация и инструкции агента (`AGENTS.md`) на уровне репозитория и проекта.
- Что происходит, если в репозитории несколько проектов и агент видит соседние папки.

## 6. Мобильный UX (решено, перенесено в functional-requirements.md)
- Поведение при потере связи: повторная подписка на SSE и полная перезагрузка истории чата, баннер «Нет связи», авто-реконнект.
- PWA: минимальный, без офлайн-кеша. Push-уведомления не нужны.
- Голосовой ввод: в MVP диктовка с клавиатуры, позже кнопка на Web Speech API. `experimental.voice.session` не используем.
- Подтверждение действий агента с телефона: правки файлов разрешены, остальное по запросу. Ответы `once`, `always`, `reject`. Автоотклонение через настраиваемое время, по умолчанию 30 минут.

## 7. Поиск
- Поиск по файлам проекта: `fs/find` или свой.
- Поиск по истории чатов: перебор через API или свой индекс.

## 8. Прототип
- Состав первого прототипа. Предложение: opencode в контейнере и один эндпоинт FastAPI, который создаёт сессию в папке проекта и стримит ответ.
- Практическая проверка пунктов из раздела «Что проверить на практике» в [opencode-integration.md](opencode-integration.md).
- Критерии успеха прототипа.
