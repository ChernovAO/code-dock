# План обсуждения

Темы, которые нужно обсудить и решить до начала реализации. По итогам решения переносятся в [overview.md](overview.md) и [functional-requirements.md](functional-requirements.md). Технические детали opencode: [opencode-integration.md](opencode-integration.md). План прототипа: [prototype-plan.md](prototype-plan.md).

## 1. Подключение к opencode (решено, перенесено в overview.md и opencode-integration.md)
- Способ подключения: FastAPI по HTTP. FastAPI проксирует запросы и SSE-события, фронтенд общается только с ним.
- Запуск opencode: отдельный контейнер (`apps/opencode`) на базе официального образа.
- Python-клиент: ручной, на `httpx2`, со своими моделями для ~25 событий. Генерации из OpenAPI нет.
- Версия opencode: 2.1.2, зафиксирована в `apps/opencode/Dockerfile`.

## 2. Безопасность на VPS
- **Не решено.** Встроенная авторизация или внешняя защита.
- **Не решено.** Публиковать ли порт 8080 только на `127.0.0.1` до выбора защиты (доступ через SSH-туннель). Сейчас он открыт на всех интерфейсах.
- **Не решено.** Можно ли использовать механизм pairing из opencode.
- Решено: изоляция агента. Граница — репозиторий, права задаёт системный конфиг opencode. Известные дыры (symlink, `shell`, `grep` по `.env`) описаны в opencode-integration.md, раздел «Права и граница агента».
- Решено: защита от записи вне проекта. Файлами занимается FastAPI на общем томе, файловые методы opencode (`fs/*`) не используем.
- Решено: хранение GitHub Personal Access Token. Только в `core`, в `remote`-URL и `.git/config` не пишется, git получает его на время команды через `GIT_ASKPASS` или `http.extraheader`.

## 3. Хранение данных
- **Не решено.** История чатов: только в БД opencode или экспорт в репозиторий (`session.export`). Пока чаты лежат в БД opencode.
- Решено: тома. Репозитории в папке на хосте (`HOST_REPOS_DIR`, в контейнерах `/repos`), БД и состояние opencode в томе `opencode-data`, системный конфиг opencode в образе.
- **Не решено.** Бэкапы.

## 4. Git
- Конфликты при pull: нужна ли помощь в их разрешении.
- Ветки: входят ли в первую версию, использовать ли worktree.
- Генерация сообщения коммита ИИ (`session.generate`).
- Взаимодействие ручных коммитов с откатом правок агента (`session.revert`).
- Библиотека для git в бэкенде: `subprocess`, pygit2 или GitPython.
- Автор коммитов (`user.name`, `user.email`): настройки, переменные окружения или профиль GitHub по токену.

## 5. Модель проекта
- Решено: проекту соответствует `location.directory` — абсолютный путь папки в `/repos`. `projectID` общий для всех папок репозитория, `subpath` — путь проекта от его корня.
- Решено: граница агента — репозиторий. Соседние проекты того же репозитория агенту доступны.
- **Не решено.** Конфигурация и инструкции агента (`AGENTS.md`) на уровне репозитория и проекта. Конфиги репозитория отключены, `AGENTS.md` проекта сам не подхватывается. Нужно выбрать: передавать его из `core` через API или доверять репозиториям. См. functional-requirements.md, «Открытые вопросы».

## 6. Мобильный UX (решено, перенесено в functional-requirements.md)
- Поведение при потере связи: повторная подписка на SSE и полная перезагрузка истории чата, баннер «Нет связи», авто-реконнект.
- PWA: минимальный, без офлайн-кеша. Push-уведомления не нужны.
- Голосовой ввод: в MVP диктовка с клавиатуры, позже кнопка на Web Speech API. `experimental.voice.session` не используем.
- Подтверждение действий агента с телефона: правки файлов разрешены, остальное по запросу. Ответы `once`, `always`, `reject`. Автоотклонение через настраиваемое время, по умолчанию 30 минут.
