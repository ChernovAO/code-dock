# План прототипа

Рабочий план первого прототипа. Контекст: [overview.md](overview.md), [discussion-plan.md](discussion-plan.md) (раздел 8), [opencode-integration.md](opencode-integration.md). Составлен 2026-10-21 по opencode V2 версии 2.1.2. Фаза A выполнена 2026-10-21, сборка и запуск в docker проверены 2026-10-23. Фаза B начата 2026-10-23, эндпоинты готовы 2026-10-26.

Решения из этого плана после реализации переносятся в [overview.md](overview.md) и [functional-requirements.md](functional-requirements.md). Потом этот файл можно удалить.

## Принятые решения

| № | Решение | Следствие |
|---|---|---|
| 1 | Свой файловый слой | FastAPI работает с файлами напрямую на общем томе. `fs/*` opencode не используем и не проксируем. |
| 2 | Ручной клиент | `httpx2` в основных зависимостях `core`. Свои модели для ~25 событий. |
| 3 | Отдельный контейнер | `apps/opencode`, образ на базе `ghcr.io/anomalyco/opencode:2.1.2`. |
| 4 | Докачка событий | **Не подтвердилась.** Журнал событий в 2.1.2 не хранится, докачки по `seq` нет. Остаётся правило «подписаться заново и перечитать историю». См. ниже. |
| 5 | Граница доступа агента — репозиторий | Политика `external_directory:*` deny. Соседние проекты одного репозитория агенту доступны. Проверено. Дыры: symlink и `shell`. |
| 6 | Репозитории на хосте | Путь задаётся `HOST_REPOS_DIR` на старте и монтируется в `core` и `opencode`. Клоны переживают рестарт контейнеров. |
| 7 | `.git` закрыт для файлового слоя | Каталоги `.git` на любой глубине, в том числе через symlink, недоступны ни на чтение, ни на запись. Git виден только через git-эндпоинты. `.gitignore`, `.gitattributes` и `.gitmodules` — обычные файлы. Принято 2026-10-23. |
| 8 | Проект — любая папка репозитория | `core` проекты не хранит. Список проектов — папки, где есть чаты. Папку для нового проекта выбирают из дерева папок. Принято 2026-10-26. |
| 9 | Symlink наружу — отказ | Если в репозитории есть symlink за его пределы или в `.git`, `core` не создаёт чат и не отправляет сообщение: 409 со списком ссылок. Список репозиториев показывает их как предупреждение. Принято 2026-10-26. |
| 10 | Формы `question` поддержаны | `core` отдаёт формы в снимке и событиях, принимает ответ и отмену. Инструмент не запрещён. Принято 2026-10-26. |
| 11 | Таймер автоотклонения и `AGENTS.md` отложены | В прототипе запросы ждут ответа без срока, `AGENTS.md` проекта агент не видит. Требования не меняются. Принято 2026-10-26. |

### Что вышло с докачкой

Проверено 2026-10-21:
- В кадрах `/api/event` нет полей SSE `id:` и `event:`. Номер `seq` лежит в `data.durable.seq`.
- `session.log?after=<seq>` не отдаёт ни прошлых, ни живых событий, в том числе с `follow=true`. Приходит только `log.synced`. Таблица `event` в БД opencode пуста.

Схема, которая работает: подписаться на `/api/event`, затем прочитать `session.message.list` и слить идемпотентно. Большинство долговечных событий несут полное состояние (`text.ended`, `tool.success`), поэтому повторы безвредны. После обрыва повторить. Буфера в FastAPI по-прежнему нет. Правило в `AGENTS.md` осталось прежним («полностью перечитать историю») и уточнено этой схемой. Подробности: [opencode-integration.md](opencode-integration.md), «События и переподключение».

## Конфигурация: репозитории на хосте

Папка `HOST_REPOS_DIR` задаётся в `.env` или окружении на старте и монтируется в `core` и `opencode` по одному пути `/repos`. Путь любой: и внутри проекта, и в любом месте на хосте. В шаблоне — `./data/repos`. Compose без переменной не стартует. Путь у сервисов должен совпадать, потому что `location.directory` в opencode абсолютный.

Реализовано:
- [`.env.example`](../.env.example): `HOST_REPOS_DIR`, `HOST_UID`, `HOST_GID`, `OPENCODE_SERVER_PASSWORD`.
- [`compose.yaml`](../compose.yaml): сервисы `opencode`, `core`, `frontend`, том `opencode-data` в `/opencode`. Фронтенд не менялся. Порт opencode наружу не публикуется.
- [`apps/opencode/Dockerfile`](../apps/opencode/Dockerfile): образ на базе `ghcr.io/anomalyco/opencode:2.1.2`, `git` и `bash`, пользователь `app` с UID и GID хоста, системный конфиг, `HOME=/opencode`.
- [`apps/opencode/opencode.jsonc`](../apps/opencode/opencode.jsonc): права и политики. Попадает в `/etc/opencode`, перекрывает любой `opencode.json` из репозитория.
- [`apps/core/Dockerfile`](../apps/core/Dockerfile): пользователь `app` с UID и GID хоста вместо `useradd --system`.
- `.gitignore` и `.dockerignore`: `data/`. Контекст сборки `core` — корень репозитория, без этого в сборку ушли бы все клоны.
- `README.md` и `AGENTS.md`: первый запуск.

Пользователь `app` создаётся с UID и GID хоста, чтобы файлы в `/repos` принадлежали владельцу репозиториев. Запись в `passwd` нужна и git.

### Отличия от черновика

Проверка нативным V2 показала, что черновик нужно править:
1. **`.env`.** Правило `read * allow` перекрывало встроенную защиту `*.env.*`: `.env.local` читался без вопроса. Правила для `*.env.*` и `*.env.example` возвращены.
2. **`.git`.** При проекте в корне репозитория путь в политике выглядит как `.git/…`, а не `…/.git/…`. Черновик пропускал запись в `.git/config` и `.git/hooks`. Добавлен шаблон `edit:.git/*`.
3. **Code Mode.** Инструмент `execute` ходил в сеть через `fetch` без вопросов и переносил сессию в другой репозиторий (`session_move`). Добавлено правило `execute` deny. Политика `execute:*` не действует.
4. **Конфиг репозитория.** `formatter` из репозитория исполнял команду, а правила агентов из репозитория снимали вопросы про `shell` и `webfetch`. В образ добавлено `OPENCODE_DISABLE_PROJECT_CONFIG=1`. Цена: `AGENTS.md` проекта не подхватывается.
5. **Режим `plan`.** Глобальный `edit * allow` отменял его запрет правок. Добавлено правило для `plan`.
6. **`COPY --chmod=644`** для конфига. При строгом umask файл в образе мог стать нечитаемым для `app`, и права молча не применились бы. Проверка в docker показала обратное: `--chmod` выставил 644 и каталогу `/etc/opencode`, который `COPY` создал сам. `app` не мог в него зайти, и системный конфиг не загружался. Каталог теперь создаётся в `RUN` (`install -d -m 755`).
7. **`/data/`** в `.gitignore` привязан к корню, чтобы не скрыть будущие каталоги `data` в исходниках.

Политики на плагины и MCP подтверждены: без них клонированный репозиторий исполняет код при открытии проекта, с ними нет.

Что вошло в проверку и что осталось дырой, описано в [opencode-integration.md](opencode-integration.md), «Права и граница агента».

## Что выяснено про opencode V2 2.1.2

Проверенное перенесено в [opencode-integration.md](opencode-integration.md). Остаётся проверить по спецификации и документации:
- `reject` отклоняет все ожидающие запросы чата сразу. Автоотклонения по таймеру в opencode нет.
- Снапшоты лежат в отдельной git-базе в каталоге данных и не трогают коммиты и индекс. Откат совместим с ручными коммитами, но перезаписывает правки файлов, которые трогал агент. Откат запрещён, пока чат выполняется.
- `session.list` имеет параметры `search`, `directory`, `project`, `subpath`.

## Ограничения и риски

Перенесены в [opencode-integration.md](opencode-integration.md), раздел «Ограничения и риски». Для прототипа важно помнить:
- **Общий том.** Через `shell` (после одобрения) агент достанет до всех репозиториев в `HOST_REPOS_DIR`. Использовать выделенную папку, а не `~/code`.
- **Папка репозиториев.** Если папки из `HOST_REPOS_DIR` нет, Docker создаст её от root, и запись упадёт. Поэтому `mkdir -p` в README.
- **Данные чатов.** `docker compose down -v` удалит том `opencode-data` вместе с чатами и ключами провайдеров. Репозитории на хосте он не затронет.
- **Docker из среды opencode недоступен.** Сборку и `compose up` проверяет пользователь. Конфиг, политики и код проверяются нативным бинарником V2.

### Слой путей и клиент: что вошло

Слой путей:
- Имя репозитория — любая одна папка, кроме `.`, `..` и `.git`: без `/` и NUL, точка в начале, пробелы и кириллица допустимы (принято 2026-10-23). Репозитории клонируют вручную, а граница держится на `realpath`, а не на алфавите имени. Корень после `realpath` обязан лежать прямо в папке репозиториев. Является ли папка git-репозиторием, проверяет список репозиториев.
- Путь внутри репозитория: относительный, без `..` и NUL. После `realpath` он обязан остаться внутри корня.
- **Каталоги `.git` закрыты на любой глубине**, в том числе через symlink. С ними работает только git-слой (решение 7).
- `follow_last=False` не разворачивает последний компонент: так удаляют и переименовывают сам symlink, а не его цель.
- Файлы читаются и пишутся только через `open_inside`: `openat` с `O_NOFOLLOW` по компонентам, без гонки с подменой каталога на symlink. Symlink на пути, даже внутрь репозитория, такой вызов не проходит.
- `external_symlinks` находит ссылки за пределы репозитория и в `.git`. Висячие ссылки наружу и каталоги, которые не удалось прочитать, тоже считаются. Вызывать при открытии репозитория и после pull.

Клиент:
- Методы: `list_sessions`, `create_session`, `get_session`, `prompt`, `messages`, `interrupt`, `permissions`, `reply_permission`, `events`. Ответы — JSON как есть. Модель есть только у конверта события (`Event`) и правила `permissions` (`Rule`).
- Ошибки — `OpencodeError` с HTTP-кодом и `_tag` из тела (`SessionNotFoundError`, `UnauthorizedError`). Код 0 — сервер недоступен, поток оборвался или ответ не понят (не JSON, нет `data`).
- Списки читаются целиком по курсору. Таймаут чтения потока событий — 45 секунд при пульсе в 15.
- Формы: `forms`, `reply_form`, `cancel_form` (2026-10-26). У `form.created` ID чата лежит в `data.form.sessionID`, `Event.session_id` это учитывает.

### Эндпоинты: что вошло

Настройки читаются на старте приложения (`lifespan`), клиент opencode один на приложение (`core.main.create_app`). Эндпоинты — `core/api.py`, репозитории и проекты — `core/repos.py`, поток чата — `core/chat.py`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/repos` | Папки первого уровня: `name`, `git`, `symlinks` (ссылки наружу и в `.git`). Файлы и ссылки за пределы папки репозиториев пропускаются. |
| `GET /api/repos/{repo}/folders?path=` | Вложенные папки без `.git` и symlink. Из них выбирают проект. |
| `GET /api/repos/{repo}/projects` | Папки с чатами: `path`, `chats`, `updated`. Собирается из всех чатов `session.list` по `location.directory` относительно развёрнутого корня репозитория. |
| `GET /api/repos/{repo}/chats?path=` | Чаты проекта: `session.list` с фильтром `directory`. Путь проверяется, но папка может не существовать: проект остаётся в списке после удаления папки. |
| `POST /api/repos/{repo}/chats` | Тело `{path, title}`, ответ 201 — чат. Репозиторий обязан быть git и без symlink наружу, папка — существовать, путь к ней — без symlink. |
| `POST /api/chats/{id}/messages` | Тело `{text}`. Перед отправкой репозиторий проверяется заново: symlink могли прийти с pull. |
| `GET /api/chats/{id}/events` | SSE чата, см. ниже. |
| `POST /api/chats/{id}/permissions/{requestID}` | Тело `{decision, message}`, ответ 204. Кроме `reject`, репозиторий проверяется, как перед сообщением. |
| `POST /api/chats/{id}/forms/{formID}` | Тело `{answer}` по ключам `fields[].key`, ответ 204. Репозиторий проверяется, как перед сообщением. |
| `DELETE /api/chats/{id}/forms/{formID}?message=` | Отмена формы, ответ 204. |

Эндпоинты `/api/chats/{id}/…` сначала читают чат. Чат вне папки репозиториев даёт 404.

Каждый новый чат получает правило `execute * deny`. Правила чата вычисляются последними, поэтому запрет Code Mode держится, даже если системный конфиг не загрузился (так уже было, см. «Найдено `live.py`»).

Ошибки:
- `PathError` и недопустимый ID чата, запроса или формы (`InvalidIdError`) — 400. Прочие `ValueError` — сбой `core`, 500.
- `PathNotFoundError` — 404.
- Репозиторий не git или с symlink наружу (`RepoError`) — 409, в теле `symlinks`.
- `OpencodeError`: 400, 404 и 409 передаются как есть, в теле `tag`. 401 — 502 с подсказкой про `OPENCODE_SERVER_PASSWORD`. Остальное, включая код 0, — 502.

SSE чата (`core/chat.py`):
- Кадры: `snapshot` (`messages`, `permissions`, `forms`), `event` (кадр opencode как есть), `reconnecting` (`detail`, `delay`), `error` (`detail`, `status`, `tag`). Каждые 15 секунд тишины FastAPI шлёт комментарий `: ping`.
- Порядок: подписка на `/api/event`, первый кадр, снимок, затем события чата. Три запроса снимка идут параллельно. События, пришедшие во время чтения снимка, идут после него.
- Фильтр по ID чата. Кадры без ID чата (`server.connected`, `shell.created`, `project.updated`) не пересылаются.
- Обрыв и любой код, кроме 401, 403 и 404 (в том числе 408 и 429): `reconnecting`, пауза 1, 2, 5, 10, 30 секунд (последняя повторяется), новая подписка и новый снимок. Коды 401, 403 и 404 (неверный пароль, чат удалён): `error`, поток заканчивается.
- Слияние делает клиент. Новый снимок заменяет его состояние, события накладываются по ключам: сообщение — `id`; текст — `assistantMessageID` и `ordinal`; вызов инструмента — `assistantMessageID` и `id`; запрос разрешения — `id` (закрывает `permission.replied` с `requestID`); форма — `id` (закрывают `form.replied` и `form.cancelled`). Долговечные события несут полное состояние, их повтор безвреден. Дельта текста, который уже закончен в снимке, — повтор, её нужно пропустить.

Не сделано в прототипе:
- Таймер автоотклонения (решение 11).
- Запросы разрешений дочерних чатов (`subagent`) приходят с ID дочернего чата, фильтр их отбрасывает. Сам opencode показывает их в родительском. Не проверено.
- Проверка symlink обходит весь репозиторий на каждом сообщении, ответе на разрешение и форму. `GET /api/repos` обходит так все репозитории. Для больших репозиториев может понадобиться кеш.
- `GET /api/repos/{repo}/projects` читает все чаты сервера: фильтры `project` и `subpath` в `session.list` не проверены.

Учесть в фазе B, это следует из проверок фазы A:
- Общий поток `/api/event` содержит события всех чатов: фильтровать по `data.sessionID`. Кадры без `id:` и `event:`, тип события в JSON.
- `permissions` в `session.create` вычисляются последними и перекрывают конфиги.
- Решение «всегда» действует на весь репозиторий: UI должен сказать об этом. Список сохранённых — `GET /api/permission/saved?projectID=…`.
- Таймер автоотклонения запросов делает `core`. Отложен (решение 11).
- Инструмент `question` создаёт форму и блокирует чат. Формы поддержаны (решение 10).
- `AGENTS.md` проекта `core` может передавать через `PUT /api/experimental/session/{id}/instructions/entries/{key}`. Отложено (решение 11).
- Git в `core`: кроме `-c core.hooksPath=/dev/null` закрыть остальные исполняемые настройки `.git/config` (`core.fsmonitor`, `core.sshCommand`, `credential.helper`).
- Путь к папке репозиториев `core` читает из переменной окружения `REPOS_DIR` на старте (в compose — `/repos`), а не хардкодит `data/repos`. Сделано.
- Symlink, ведущие за пределы репозитория, открывают агенту ключи провайдеров и пароль opencode (см. opencode-integration.md, «Что не защищено»). `core` ищет такие ссылки в списке репозиториев, при создании чата и перед каждым сообщением и отказывает (решение 9). После pull — вместе с git-эндпоинтами.
- В образе `core` нет `git` (база `python-slim`, проверено). Поставить его в `apps/core/Dockerfile` вместе с первым git-эндпоинтом.
- У пользователя `app` в образе `core` нет домашнего каталога и глобального gitconfig. Без `user.name` и `user.email` `git commit` упадёт. Откуда их брать, не решено (functional-requirements.md, «Открытые вопросы»).
