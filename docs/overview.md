# Code Dock: обзор проекта

## Что это
Code Dock — self-hosted веб-интерфейс для работы с ИИ-агентом с телефона. Это обёртка над **opencode** и **git**. Она даёт мобильный UX, как у Open WebUI, плюс проекты с файлами и версионированием.

## Зачем нужен
Сейчас у автора два способа работать с ИИ, и оба неудобны:
- **Бесплатные веб-чаты.** В них нет проектов, файлов и истории изменений.
- **opencode на ноутбуке.** Он мощный, но с телефона недоступен.

Проблемы, которые решает проект:
1. Нет доступа к opencode с телефона.
2. Бесплатные чаты не умеют вести проекты.
3. Результаты работы с ИИ нигде не версионируются и не синхронизируются с GitHub.
4. Не хочется хранить проекты в сторонних облачных сервисах.

Готовые решения (opencode web, Open WebUI, Claude Projects) не подходят по трём причинам: нет git-интеграции, есть зависимость от облака и вендора, и нет работы с файлами проекта.

## Для кого
Open source для всех, кто хочет развернуть свой инстанс. Один инстанс обслуживает одного пользователя.

## Ключевые понятия
- **Репозиторий** — git-репозиторий на GitHub, клонируется на сервер по URL. В одном репозитории может быть несколько проектов.
- **Проект** — тематическая папка внутри репозитория с файлами и связанными чатами.
- **Чат** — сессия с ИИ внутри проекта. ИИ может читать и менять файлы проекта.
- **Синхронизация** — commit, push и pull выполняются вручную через UI.

## Основной сценарий
Долгая работа над документом с телефона. Пользователь открывает проект, итеративно правит тексты и заметки вместе с ИИ, исследует и обсуждает темы. Потом вручную коммитит и пушит изменения в GitHub.

## Принципы
- Свой агент не пишем, вся логика ИИ остаётся в opencode.
- Модели и провайдеры настраиваются средствами opencode.
- Данные принадлежат пользователю: они лежат в его git-репозиториях на его сервере.
- Агент видит только свой репозиторий. Выход за его пределы запрещён, команды и сеть требуют подтверждения.
- Mobile-first.

## Архитектура
- Фронтенд: React + TypeScript.
- Бэкенд: FastAPI (Python). Единственная точка входа для фронтенда: проксирует запросы и SSE-события в opencode, сам работает с git и файлами.
- Агент: opencode в отдельном контейнере, версия 2.1.2. Доступен только бэкенду во внутренней сети docker и закрыт паролем.
- Данные: репозитории лежат в папке на хосте (`HOST_REPOS_DIR`) и монтируются в бэкенд и opencode как `/repos`. БД opencode с чатами лежит в томе docker `opencode-data`.
- Запуск: docker compose.
- Деплой: VPS в интернете.

## Не входит в проект
- Свой ИИ-агент или движок.
- Нативное мобильное приложение (только веб).
- Многопользовательская работа.
- Разработка кода и замена IDE. Фокус на текстах, заметках и исследованиях.

## Критерии успеха
- Над документом можно работать целиком с телефона, без обращений к ноутбуку.
- Проект поднимается одной командой (`docker compose up`).

## Открытые вопросы
- Как защищать доступ на публичном VPS: встроенная авторизация или внешняя защита. Решение отложено.
