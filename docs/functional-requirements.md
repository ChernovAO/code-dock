# Функциональные требования

Документ описывает, что должен уметь Code Dock. Контекст и цели проекта: [overview.md](overview.md).

## 1. Репозитории и проекты

**Модель.** Репозиторий GitHub может содержать несколько проектов. Проект — это папка внутри склонированного репозитория.

- Клонировать репозиторий по URL.
- Выбрать существующую папку в склонированном репозитории как проект.
- Создать новую папку в репозитории и сделать её проектом.
- Показывать список склонированных репозиториев и проектов в них.

Проектом может стать любая папка репозитория. Список проектов не хранится: это папки, где есть чаты.

**Опасные symlink.** Если в репозитории есть symlink за его пределы или в `.git`, агент через него читает и пишет мимо границы. С таким репозиторием агент не работает: создать чат и отправить сообщение нельзя, UI показывает список ссылок.

**Хранение.** Репозитории лежат в папке на хосте (`HOST_REPOS_DIR`), которая монтируется в контейнеры как `/repos`. Клоны переживают рестарт контейнеров. В прототипе репозитории клонирует пользователь на хосте, клонирование из UI добавляется после прототипа.

**Доступ к GitHub.** Через Personal Access Token. Его можно задать в настройках приложения или через переменную окружения. Токен живёт только в бэкенде: его нельзя писать в `remote`-URL и `.git/config` и отдавать на фронтенд, иначе он окажется на общем томе, где его увидит агент.

## 2. Чаты

- Несколько чатов внутри проекта: список, создание, переименование, удаление.
- Стриминг ответов по мере генерации.
- Показ действий агента: какие файлы он читает и правит (tool calls).
- Выбор модели и режима (агента) из UI.
- Прерывание генерации.
- Запросы разрешений: подтверждение действий агента с телефона (см. ниже).
- Вопросы агента (`question`): UI показывает форму, отправляет ответ или отменяет её. Пока форма открыта, чат стоит.
- Прикрепление файлов и изображений к сообщению, упоминание файла проекта.
- Голосовой ввод сообщения: в первой версии через диктовку с клавиатуры телефона. Отдельная кнопка на базе браузерного распознавания (Web Speech API) добавляется после первой версии.
- Рендер markdown в ответах.

### Работа в фоне
Если пользователь закрыл вкладку или потерял связь, агент продолжает работу на сервере. При возвращении UI заново подписывается на SSE, затем полностью перечитывает историю чата (`session.message.list`) и сливает её с живыми событиями. Докачки по номеру события нет: журнал событий opencode 2.1.2 не хранится. Буфера событий в FastAPI тоже нет.

При обрыве связи UI показывает баннер «Нет связи» и автоматически переподключается. Чат остаётся доступным для чтения, ввод блокируется до восстановления связи. Очереди сообщений в офлайне нет.

### Подтверждение действий агента
- По умолчанию чтение и правка файлов репозитория разрешены без вопросов, в том числе в соседних проектах того же репозитория. Остальное (команды, сеть) требует подтверждения. Выход за пределы репозитория и правка `.git` запрещены без вопросов. Файлы `.env` читаются только с подтверждением.
- В UI доступны три ответа: «один раз», «всегда», «отклонить» (`once`, `always`, `reject`).
- Решение «всегда» действует на весь репозиторий, а не на один проект. UI должен сказать об этом при выборе. Сохранённые решения можно просмотреть и отозвать в настройках (`permission.saved.*`).
- Неотвеченный запрос автоматически отклоняется через настраиваемое время, по умолчанию 30 минут (переменная окружения). Таймер реализует FastAPI: в opencode его нет. В прототипе таймера нет. Push-уведомлений нет, поэтому при возвращении в чат UI показывает незакрытые запросы (`permission.request.list`), а в списке чатов отмечает чаты, которые ждут ответа.

## 3. Файлы проекта

- Просмотр дерева файлов и содержимого файлов.
- Markdown-превью.
- Ручное редактирование файлов без ИИ.
- Загрузка файлов с телефона в проект.
- Скачивание файла.
- Просмотр diff относительно последнего коммита.
- Откат изменений (в том числе правок агента).
- Поиск по проекту (по файлам и по истории чатов).

## 4. Git

Синхронизация выполняется вручную, автокоммитов нет.

- Status и diff.
- Commit с сообщением.
- Push и pull с GitHub.
- История коммитов.

## 5. Интерфейс

- Mobile-first веб-интерфейс.
- Тёмная и светлая темы.
- Минимальный PWA: манифест, иконки, режим standalone для установки на экран «Домой». Офлайн-кеша и push-уведомлений нет.

## Открытые вопросы
- **Хранение истории чатов.** Только в opencode на сервере или экспорт в репозиторий. Не решено. Пока чаты лежат в БД opencode (том `opencode-data`), `docker compose down -v` удаляет их вместе с ключами провайдеров.
- **Защита доступа на VPS.** Встроенная авторизация или внешняя защита. Решение отложено. Opencode закрыт паролем и недоступен снаружи, вопрос касается входа в веб-интерфейс. Сейчас compose публикует порт 8080 на всех интерфейсах. После фазы B любой, кто до него дотянется, сможет писать агенту и одобрять команды. До решения не открывайте порт в интернет.
- **`AGENTS.md` проекта.** В образе конфиги репозитория отключены: они исполняют код и обходят права. Поэтому `AGENTS.md` проекта сам не подхватывается. Нужно решить: передавать его из `core` через API (проверено, работает) или доверять конфигам репозиториев.
- **Конфликты при pull.** Пока не обсуждали, нужна ли помощь в их разрешении.
- **Ветки.** Не вошли в первую версию, нужно подтвердить.
- **Генерация сообщения коммита ИИ.** Не обсуждали.
- **Автор коммитов.** Не решено, откуда `core` берёт `user.name` и `user.email`: из настроек, из переменных окружения или из профиля GitHub по токену. Без них `git commit` не работает.
